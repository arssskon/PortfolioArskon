02 — Context & Task

A catalog of 80,000+ products and two different buyers in one product

The client is an online store for interior goods (posters, paintings, print‑on‑demand) with delivery across Russia. The business has two streams: B2C retail (ready catalog) and B2B — branded content production for companies.

The designer's task: build an information architecture that doesn't collapse under content volume, and adapt it to three screen sizes without losing usability.

Format A3–A0 Price from 532 ₽ Delivery from 150 ₽ Production 1–3 days Pay on delivery
02.1 — Insight / Business Logic

Two demand streams in one product

The site is built on three intersecting scenarios: B2C‑retail (ready catalog), B2C‑custom (print from your own image) and B2B (branded content for business). Each final catalog category is a separate SEO landing page — users typically arrive not "at the catalog in general," but at a specific thematic page (by fandom, actor, city), and from there explore adjacent themes through the mega‑menu.

02.2 — Insight / User Path

Six steps that defined the interface architecture

01

Entry via thematic interest — SEO page of a specific category

02

Navigation within the theme — switching between subtopics via mega‑menu

03

Reducing uncertainty — personalization quiz and image upload as alternative to browsing

04

Product configuration — size, material, frame

05

Checkout and payment — pay‑on‑delivery lowers the decision barrier

06

Alternative branch — gift certificate bypasses the specific product selection funnel

This step‑by‑step logic defined the interface architecture — screens became a consequence of a thought‑out scenario, not the other way around.

03 — Process / Information Architecture

A flat list of 25+ subcategories overloads navigation — collapsed hierarchy to 5 categories

1920 — desktop · mega‑menu on hover
Problem

The "Printing" category had 25+ subcategories (business cards, blanks, booklets, stands, catalogs, certificates, and more). A flat list visually overwhelms and reduces findability.

Solution

The top level is collapsed to 5 categories. Desktop — mega‑menu in 4 columns on hover. Mobile — vertical accordion with the same hierarchy.

480 — mobile · vertical accordion
04 — Process / Adaptive Design

Every key screen built for 480 / 768 / 1920 — with grid restructuring, not compression

On desktop, hero, image upload form and quiz/chat widgets are visible simultaneously — on mobile they stack by priority.

1920 — desktop · 1024 — wide tablet · 768 — tablet · 480 — mobile
05 — Process / Personalization

Quiz + image upload — reducing choice paralysis across 80,000+ items

The "Which poster suits you best" quiz reduces selection friction in the catalog. The "Upload your image" form enables print from a customer's own photo.

Image upload configurator — size, material, paper type
06 — Process / Gift Certificate Configurator

The most complex interactive node in the project

Value selection (6 denominations + custom, with limits), delivery method (email / PDF), recipient form with validation, live price recalculation.

Separately — "who to gift" segmentation across 6 scenarios and a B2B upsell block placed below the page to avoid competing with the retail flow.

Certificate configurator — denomination, delivery, live total
Gift certificate page — scenarios, steps, occasions
Six gift scenarios segmentation
B2B upsell placed below retail flow — no competition between streams
07 — Process / B2B as Separate Branch

Branded content — a standalone landing within the site

The "Branded Content" service is built as a standalone landing with its own structure: what's included → examples → stages → pricing table → reviews → FAQ — without mixing with the retail catalog.

08 — Process / System & Edge States

States that often fall out of portfolios — but make up real UX

Cookie banner across all three adaptive breakpoints without blocking key CTAs. Anti‑bot check with an explanatory message instead of a dry error — preserving trust at an unpleasant moment.

1920 — desktop
768 — tablet
480 — mobile
Cookie banner · 1920 / 768 / 480 — does not block key CTAs
Anti‑bot check · Explanatory text instead of a generic error message
09 — Constraints

What shaped the decisions

01

Working within the client's existing platform — standard e‑commerce engine with pre‑built components

02

Preserving brand style across all new modules — certificates and B2B must not feel "bolted on"

03

Merging B2C and B2B in one design system without visual conflict between user types

11 — Reflection
"The most non‑trivial challenge in the project was not drawing screens, but the catalog's information architecture: 25+ printing subcategories had to fit into a structure equally understandable in a large mega‑menu and a collapsed mobile accordion. If starting over, I'd run a more formal card sorting exercise with real users instead of intuitive grouping."
